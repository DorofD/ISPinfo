# ISPinfo

Вся информация о провайдерах в одном месте.

Данное приложение упрощает процесс составления заявок интернет-провайдерам.
При возникновении проблемы с интернет-каналом более нет необходимости искать всю информацию о провайдере в разных местах и составлять заявку вручную.
Достаточно выбрать нужный магазин и провайдера - заявка сформируется автоматически, останется только отправить.

## Возможности

- Поиск договоров с провайдерами по PID магазина или названию магазина
- Автоматическая генерация текста заявки в техподдержку провайдера (юр. лицо, договор, адрес, IP, контакты поддержки)
- Актуализация базы договоров импортом из Excel (`.xlsx`)
- Управление пользователями (роли `Admin` / `Support`)
- Аутентификация: локальные пароли или корпоративный LDAP

## Требования

- Python 3.10+ (для локального запуска)
- Docker + Docker Compose (для контейнерного запуска, рекомендуемый способ)
- LDAP-сервер (только если используются LDAP-пользователи)

## Развертка через Docker Compose (рекомендуется)

Приложение разворачивается одним контейнером, база данных (SQLite) хранится в каталоге `./data` на хосте и переживает пересборку.

1. Создайте файл конфигурации на основе шаблона и заполните LDAP-переменные:

   ```bash
   cp .env.example .env
   ```

   | Переменная | Описание |
   |------------|----------|
   | `LDAP_SERVER` | адрес LDAP-сервера, например `ldap://ldap.example.local` |
   | `LDAP_USER` | DN сервисной учётки для поиска пользователей |
   | `LDAP_USER_CN` | CN сервисной учётки |
   | `SEARCH_USER_CATALOG` | DN каталога, в котором ищутся пользователи |

   > Переменные обязательны даже если LDAP не используется — без них приложение не стартует.

2. Соберите и запустите (compose-файл лежит в каталоге `docker/`):

   ```bash
   docker compose -f docker/docker-compose.yml up -d --build
   ```

3. Откройте приложение: `http://<IP-машины>:8080`

   Порт проброшен на всю локальную сеть. При первом старте база данных и пользователь `admin` (пароль: `1488`) создаются автоматически. Функции смены пароля в приложении нет — при необходимости хеш меняется напрямую в БД (`data/database.db` в Docker, `src/database.db` при локальном запуске; таблица `users`), хеш генерируется через `werkzeug.security.generate_password_hash`.

Полезные команды:

```bash
docker compose -f docker/docker-compose.yml logs -f        # логи приложения
docker compose -f docker/docker-compose.yml down           # остановить (данные в ./data сохраняются)
docker compose -f docker/docker-compose.yml up -d --build  # пересобрать после изменений кода
```

> Альтернатива: `cd docker && docker compose up -d --build` — пути в compose-файле указаны относительно него, поэтому оба варианта эквивалентны.

## Локальный запуск (без Docker)

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # заполнить LDAP-переменные
python src/init_db.py         # создать БД и пользователя admin (1488)
python src/app.py             # http://localhost:5000
```

## Импорт данных

База договоров обновляется полным импортом файла `.xlsx` (раздел «Актуализация», доступен роли `Admin`). Формат: первая строка — заголовок, далее колонки в порядке:

`PID, Магазин, Канал, IP, Юр. лицо, Провайдер, Договор, Адрес, Телефон поддержки, Почта поддержки`

Пример файла: `src/testContracts.xlsx`.
⚠️ Импорт полностью заменяет существующие данные.
